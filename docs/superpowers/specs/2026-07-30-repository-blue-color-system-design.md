# 仓库蓝配色统一设计

## 目标

将 Agent Compose UI 统一为专业企业开发工具风格的“仓库蓝”深色配色。通过单一中性色阶、单一品牌蓝和严格的语义状态色，消除组件间颜色不一致与无功能含义的彩色噪音。

## 范围

本次只修改颜色相关声明，包括 CSS 自定义属性、颜色字面量、`color-mix()`、透明色和仅表达颜色的阴影值。

不得修改以下内容：

- 字体、字号、字重、行高和字间距
- 元素尺寸、内外边距、间距和定位
- 页面布局、网格、弹性布局和响应式断点
- 边框宽度、边框样式和圆角
- 非颜色阴影参数
- 动画、过渡、透明度、模糊效果和交互逻辑
- HTML/Svelte 结构、文案、图标和组件行为

若某条复合声明同时包含颜色与非颜色参数，只替换其中的颜色值。

## 核心色板

| 角色 | 色值 | 用途 |
| --- | --- | --- |
| `--bg-primary` | `#0D1117` | 页面底色、编辑器深层背景 |
| `--bg-secondary` | `#161B22` | 侧栏、面板、模态框一级表面 |
| `--bg-tertiary` | `#21262D` | 卡片、输入框、悬浮与选中表面 |
| `--border-color` | `#30363D` | 默认边框与分隔线 |
| `--text-primary` | `#F0F6FC` | 标题、正文和高优先级信息 |
| `--text-secondary` | `#8B949E` | 描述、标签和次级信息 |
| `--text-muted` | `#6E7681` | 占位、时间戳和低优先级信息 |
| `--accent-blue` | `#1F6FEB` | 主操作、选中态、焦点和链接 |
| `--accent-blue-bright` | `#58A6FF` | 深色背景上的强调文本与代码高亮 |
| `--accent-green` | `#3FB950` | 成功、在线和正常状态 |
| `--accent-yellow` | `#D29922` | 警告、等待和草稿状态 |
| `--accent-red` | `#F85149` | 错误、失败和危险操作 |
| `--accent-purple` | `#A371F7` | 完成类特殊状态或既有文件类型语义 |
| `--accent-orange` | `#DB6D28` | 严重警告或既有文件类型语义 |

## 使用规则

### 表面层级

页面和编辑器底层使用 `--bg-primary`，侧栏与常规面板使用 `--bg-secondary`，卡片、输入框、悬浮和选中态使用 `--bg-tertiary`。不得为单个组件创建未经定义的新灰色表面。

### 品牌蓝

`--accent-blue` 只用于可操作或已选中的界面元素：主按钮、活动导航、活动标签、链接、焦点边框和操作图标。深色背景上的小号强调文字可使用 `--accent-blue-bright`。品牌蓝不用于普通标题、装饰边框或无交互信息。

### 语义色

绿色、黄色、红色只表达成功、警告和错误。紫色与橙色仅保留给已有且必要的特殊状态或文件类型，不作为随机装饰色。同一状态在所有页面保持同一颜色。

### 交互态

悬浮、按下与弱强调背景优先通过核心色和现有背景的 `color-mix()` 生成，不引入新的独立十六进制色。焦点态统一使用品牌蓝，并保留现有焦点轮廓尺寸与偏移。

### 覆盖层和阴影

遮罩与阴影继续使用黑色透明值，只统一颜色部分，不调整透明度、偏移、模糊或扩散参数。

## 实施策略

1. 更新 `src/app.css` 中的全局颜色 token，并补充亮蓝 token。
2. 遍历 `src/**/*.svelte` 与 `src/**/*.css` 的颜色声明。
3. 将重复的硬编码颜色映射到全局 token 或基于 token 的 `color-mix()`。
4. 保留有明确业务含义且核心色板无法表达的颜色；若保留，必须归入明确语义，而不是组件私有装饰色。
5. 对源码差异进行约束检查，确认没有颜色以外的 CSS 属性、组件结构或逻辑变化。

## 验证标准

- 全局页面采用一致的三层深色表面。
- 主操作、活动导航、活动标签、链接和焦点使用统一品牌蓝。
- 成功、警告、错误在所有页面语义一致。
- 不再存在可由核心 token 表达的重复硬编码颜色。
- 颜色对比满足可读性要求，正文、控件和状态信息在深色背景上清晰可辨。
- 自动化测试通过。
- Git 差异仅包含颜色声明和本设计文档，不包含布局、字号、圆角或其他视觉结构变化。
