# Skills 与数据挂载界面重设计

## 目标

重新组织 YAML 编辑器下方的 `Skills` 和“数据与挂载”面板，使展示密度、操作入口、状态反馈和文件编辑方式与现有“脚本文件”和“Workspace 文件”保持一致，同时保留两类资源各自的业务语义。

本次只调整界面组织和交互方式，不改变 YAML 格式、Go 网关 API、Volume 生命周期、并发冲突保护或物理数据删除规则。

## 设计原则

- Skills 是项目文件资源，采用文件管理界面。
- 数据卷和挂载是声明、关联与生命周期资源，采用资源管理界面。
- 常用操作放入顶部工具栏，创建配置放入弹窗，不在主面板长期铺开表单。
- 列表负责导航，详情区域负责查看和编辑；危险操作继续使用明确的二次确认。
- 沿用现有颜色变量、边框、按钮、空状态、状态提示和左右分栏，不创建独立视觉体系。

## Skills 面板

### 布局

Skills 面板采用与“脚本文件”和“Workspace 文件”一致的左右分栏：

- 左侧为 Skill 列表，宽度与现有文件树接近，可滚动。
- 右侧为所选 Skill 的详情和 `SKILL.md` 编辑区。
- 左右区域之间使用现有分隔线；面板填满资源区域，不使用独立卡片包裹整个界面。

### 顶部工具栏

工具栏提供：

- `新建 Skill`
- `上传 Skill`
- `刷新`

新建操作使用弹窗输入 Skill 名称和目标 Agent。创建成功后自动选中新 Skill，并在右侧打开有效的 `SKILL.md` 模板。

上传操作仅覆盖现有后端能够安全支持的能力：

- 上传单个 UTF-8 `SKILL.md` 到新建 Skill；
- 上传前输入 Skill 名称并选择目标 Agent；
- 前端先调用现有目录创建能力，再通过 multipart 单文件接口写入 `<skill-name>/SKILL.md`；
- 上传和 YAML 更新任一步失败时显示明确错误，并尽可能回滚本次新建目录；
- 冲突时不覆盖磁盘内容，保留用户选择。

现有后端没有 ZIP 解包接口，因此本次不支持 ZIP Skill 包，也不展示 ZIP 或目录包上传入口。

### 左侧列表

- 每项显示 Skill 名称和选中状态。
- 当前 YAML 已引用的 Skill 可显示引用 Agent 数量。
- 空列表使用与 Workspace 一致的居中空状态。
- 加载失败在列表区域展示错误和重试按钮，不占用编辑区域。

### 右侧编辑区

- 标题显示 `<skill-name>/SKILL.md`。
- 标题栏显示关联 Agent、保存状态，并提供保存和删除操作。
- 编辑器使用等宽字体、充满可用高度，视觉上对齐现有脚本编辑器。
- 保存冲突保留本地草稿，提供“重新加载磁盘内容”。
- 切换 Skill 前若存在未保存内容，必须确认放弃或留在当前 Skill。

### 删除

删除仍按现有安全顺序执行：先展示引用 Agent，再更新 YAML，最后删除文件。YAML 已更新但文件删除失败时保留重试入口。

## 数据与挂载面板

### 布局

数据与挂载采用“资源导航 + 详情”的左右结构，但不把资源伪装成文件：

- 左侧按“持久数据”“依赖缓存”“共享目录”分组列出当前资源。
- 右侧展示选中资源的业务详情、挂载关系和允许的操作。
- 顶部工具栏提供 `创建数据卷`、`挂载资源`、`应用 YAML` 和 `刷新`。

没有资源时展示业务空状态，并提供主要创建入口。

### 创建数据卷

点击“创建数据卷”打开弹窗，字段包括：

- 逻辑名称；
- 目标 Agent；
- 容器内挂载路径。

提交后沿用现有稳定系统名称、项目归属标签、目标路径冲突检查和 YAML 原位修改逻辑。

### 挂载资源

点击“挂载资源”后先选择资源类型：

- 挂载已有数据卷；
- 启用依赖缓存；
- 挂载共享目录。

弹窗根据类型只展示必要字段：

- 已有卷：卷、目标 Agent、目标路径；
- 缓存：Agent 和缓存预设；
- 共享目录：目录、目标 Agent、目标路径、只读/读写权限。

共享目录不可写时，读写选项不可用并解释原因。

### 左侧资源列表

- 持久数据项显示逻辑名称和挂载数量。
- 缓存项显示预设名称和使用它的 Agent。
- 共享目录项显示目录名称及只读/读写状态。
- 选中状态、悬停和键盘导航与现有文件树一致。

### 右侧详情

持久数据详情包含：

- 逻辑名称、系统卷名和托管状态；
- 当前 Agent 挂载关系；
- 卸载、删除声明和物理删除入口；
- 对可浏览的本地托管卷展示文件浏览器。

缓存详情包含预设目标路径、关联 Agent，以及启用/停用入口。共享目录详情包含展示名称、权限、目标路径和卸载入口。

Volume 文件浏览器沿用 Workspace 的文件树与预览结构：左侧目录/文件列表，右侧文件预览或编辑；上传、新建目录和刷新位于局部工具栏。

### 应用与删除

- YAML 编辑操作继续即时写入编辑器草稿。
- `应用 YAML` 使用现有项目预览、确认和应用流程，不创建第二套保存逻辑。
- 删除声明与删除实际数据继续分开表达。
- 物理删除必须在 YAML 应用成功后执行，并保留重声明、并发操作和失败重试保护。

## 状态和错误处理

- 加载状态限定在对应列表或详情区域，避免整页闪烁。
- 成功反馈优先使用现有 Toast；需要用户继续处理的冲突和部分失败保留在面板内。
- 所有异步结果继续按项目、Skill 或 Volume 身份隔离，切换项目后不得污染新页面。
- 弹窗打开时锁定背景交互，支持 Escape、焦点恢复和键盘焦点循环。
- 正在保存、应用或删除时禁用会产生冲突的操作。

## 组件边界

- `SkillPanel.svelte` 负责整体布局和状态编排。
- Skill 新建/上传弹窗拆成独立组件；上传只调用现有单文件 multipart API，文件编辑区域保持独立职责。
- `DataMountPanel.svelte` 负责资源选择和生命周期编排。
- 创建卷和挂载资源分别使用独立弹窗组件。
- Volume 文件管理复用或重构为与 Workspace 文件树、预览一致的小组件，但不改变 Volume API。
- YAML mutation、Skill API、Volume API 和删除保护模块保持独立，不把业务逻辑迁入样式组件。

## 测试与验收

- Skills：覆盖新建、单个 `SKILL.md` 上传、选择、编辑、未保存切换确认、冲突、引用删除和项目切换。
- 数据与挂载：覆盖三类资源导航、各弹窗字段、创建/挂载、应用、卸载、两阶段删除及失败重试。
- 可访问性：覆盖工具栏命名、列表选择状态、弹窗焦点、Escape 和键盘导航。
- 回归：现有 YAML mutation、API、并发保护、删除保护和 Workspace/脚本组件测试必须继续通过。
- 视觉验收：两个面板使用与脚本/Workspace 相同的分栏、工具栏、空状态、边框和控件密度；主页面不再长期展示多个创建表单。

## 非目标

- 不修改 agent-compose daemon。
- 不改变项目 YAML 协议。
- 不新增系统级权限模型。
- 不改脚本、Workspace、镜像或系统设置页面。
- 不把数据卷抽象成普通文件夹。
